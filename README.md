# claudeguard

Пускает Claude (десктоп-приложение и Claude Code) через выбранный прокси или VPN. Если прокси или VPN упали, Claude остаётся без сети и не уходит напрямую (kill switch).

macOS, Windows и Linux (Ubuntu/Debian, Fedora, Arch, SteamOS), один бинарник на Go с установщиком под каждую систему. Серверы переключаются в локальной панели настроек или в значке в строке меню, без перезапуска Claude. Новый SSH-сервер настраивается прямо в панели: нужны адрес и пароль.

## Как это устроено

Защита из двух слоёв:

1. **Kill switch в системном файрволе.** Все прямые соединения к сетям Anthropic запрещены:
   `160.79.104.0/21`, `153.61.208.0/20`, `153.61.224.0/22`, `2607:6bc0::/48`
   ([официальный список](https://platform.claude.com/docs/en/api/ip-addresses)). На них живут claude.ai, api.anthropic.com и эндпоинты Claude Code.
   - macOS: правила pf в анкере `com.apple/claudeguard`. `/etc/pf.conf` не меняется. LaunchDaemon восстанавливает правила при загрузке и проверяет их каждые 15–60 с.
   - Windows: правило Windows Firewall в группе `claudeguard`. Правила блокировки там сильнее правил разрешения, а сами правила переживают перезагрузку.
   - Linux: таблица nftables `inet claudeguard` (цепочки output и forward, так что контейнеры и виртуальные машины на этой машине тоже закрыты). Нет `nft` — та же логика через iptables, цепочка `CLAUDEGUARD`. Юнит systemd `claudeguard-firewall.service` ставит правила до поднятия сети, таймер раз в минуту возвращает их, если другой инструмент сбросил весь набор правил.

   Это правила ОС, а не процесс. Если claudeguard упадёт, Claude обновится или кто-то запустит его в обход лаунчера, прямого пути к Anthropic всё равно нет.

2. **Локальный HTTP-прокси** `127.0.0.1:41080` → активный сервер из списка (SSH-хост, `socks5://` или `http://`). Нужен потому, что Claude Code не умеет работать с SOCKS. Имена хостов уходят в upstream нерезолвленными, так что DNS для Claude резолвится на стороне прокси. Если upstream недоступен, мост отвечает 502 и напрямую не ходит.
   - Claude Code: в `~/.claude/settings.json` → `env` прописываются `HTTPS_PROXY` и `HTTP_PROXY`. Исходный файл сохраняется в `settings.json.claudeguard.bak`.
   - Десктоп: ярлык «Claude via Proxy» перезапускает приложение с `--proxy-server=http://127.0.0.1:41080`. Chromium с этим флагом напрямую не ходит.

### Режимы

| Режим | Флаг | Что разрешено к Anthropic |
|---|---|---|
| Только прокси | (по умолчанию) | только через прокси. С любого интерфейса напрямую нельзя, даже через VPN |
| Прокси или VPN | `--allow-tunnels` | через прокси и через VPN-интерфейсы (`utun*`, `tun*`, `tap*`, `ipsec*`, `ppp*`, `wg*`). VPN отключился → блок |

Если Claude ходит через системный VPN (например, AmneziaWG), нужен `--allow-tunnels`. Без него прямой трафик в VPN тоже режется, и работает только путь через прокси.

## Установка

Файлы лежат в [Releases](https://github.com/VitalyDubovets/claudeguard/releases). Терминал не нужен: установщик сам спросит пароль администратора, поставит всё и откроет панель, где выбирается сервер.

> **Во время установки текущие соединения Claude к Anthropic рвутся** (иначе старые продолжали бы идти напрямую). В режиме «Пускать через VPN» с включённым VPN Claude переподключится сам, иначе перезапусти его через «Claude via Proxy».

| Система | Файл | Что делать |
|---|---|---|
| macOS (Apple silicon и Intel) | `Claudeguard-X.Y.Z.dmg` | открыть, перетащить Claudeguard в «Программы», запустить |
| Windows 10/11 | `ClaudeguardSetup-X.Y.Z-amd64.exe` (или `-arm64`) | двойной щелчок |
| Ubuntu, Debian | `claudeguard_X.Y.Z_amd64.deb` | `sudo apt install ./claudeguard_*.deb`, затем «Claudeguard» в меню приложений |
| Fedora | `claudeguard-X.Y.Z-1.x86_64.rpm` | `sudo dnf install ./claudeguard-*.rpm`, затем «Claudeguard» в меню |
| Arch, Manjaro | `claudeguard-X.Y.Z-1-x86_64.pkg.tar.zst` | `sudo pacman -U claudeguard-*.pkg.tar.zst`, затем «Claudeguard» в меню |
| SteamOS и остальные | `claudeguard_X.Y.Z_linux_amd64.tar.gz` | распаковать, `./claudeguard install` |

Для ARM-машин на Linux есть те же пакеты с `arm64` / `aarch64` в имени.

Удаление: «Удалить Claudeguard…» внизу панели (на Windows ещё и в «Приложения и возможности») или `claudeguard uninstall`. Сначала снимается kill switch: если отменить запрос пароля, ничего не тронуто и защита цела. Потом всё возвращается как было до установки:

- `~/.claude/settings.json` — к прежнему виду. Если после установки файл никто не менял, он восстанавливается байт в байт. Если менял — убираются только переменные прокси, а те, что стояли до Claudeguard, возвращаются. Файл, которого до установки не было, удаляется.
- Фоновый прокси, значок, ярлыки, автозапуск, правила файрвола и системные службы убираются.
- Папка с конфигом удаляется целиком: список серверов, ключ Claudeguard, доверенные ключи хостов, данные окна панели.
- С серверов, настроенных в панели, снимается ключ Claudeguard (строка в `~/.ssh/authorized_keys`). Если сервер не ответил, программа скажет, где строка осталась.
- macOS: Claudeguard.app переносится в Корзину. Windows: папка программы удаляется через несколько секунд после закрытия. Linux: сам пакет остаётся, его убирает менеджер пакетов.

Claude после удаления надо перезапустить обычным способом: запущенный через «Claude via Proxy» продолжает искать прокси, которого уже нет.

### macOS

При первом запуске Claudeguard.app спрашивает пароль администратора в системном окне и ставит:

- копию программы и правила pf в `/Library/Application Support/claudeguard` (каталог доступен на запись только root) и LaunchDaemon `com.claudeguard.firewall`;
- прокси как LaunchAgent `com.claudeguard.proxy`, лог в `~/Library/Logs/claudeguard.log`;
- «Claude via Proxy.app» в `~/Applications` (запускай Claude через него);
- значок в строке меню (LaunchAgent `com.claudeguard.tray`);
- команду `claudeguard` для терминала (ссылка в `/usr/local/bin`).

Потом тот же Claudeguard.app просто открывает панель. Новая версия ставится так же: заменить приложение в «Программах» и запустить.

Приложение не подписано сертификатом Apple (нужен платный Developer ID), поэтому при первом запуске macOS скажет, что не может проверить разработчика. Открой «Системные настройки → Конфиденциальность и безопасность» и нажми «Всё равно открыть». Если Developer ID есть, `SIGN_ID="Developer ID Application: …" ./build.sh` подпишет приложение им.

### Windows

`ClaudeguardSetup` спрашивает подтверждение, показывает запрос UAC и ставит:

- программу в `%LOCALAPPDATA%\claudeguard`, прокси стартует при входе в систему (ключ `HKCU\...\Run`);
- ярлыки «Claude via Proxy» и «Claudeguard» на рабочем столе и в меню «Пуск», значок в области уведомлений;
- запись в «Приложения и возможности» для удаления.

Файл не подписан, SmartScreen предупредит: «Подробнее» → «Выполнить в любом случае».

- SSH-серверы используют встроенный OpenSSH (`ssh.exe`, есть в Windows 10/11).
- Режим «Пускать через VPN» на Windows вешает блок только на физические адаптеры (`Get-NetAdapter -Physical`), так что Wintun/TAP (WireGuard, AmneziaWG, OpenVPN) остаются разрешены. Адаптер, подключённый позже (USB-модем, новая сетевая карта), не покрыт, пока не нажмёшь «Применить» в панели ещё раз.
- Нужен включённый Windows Firewall. Если его заменил сторонний файрвол, правило не действует.

### Linux

Пакет кладёт `/usr/bin/claudeguard`, пункт меню и значок. Сама защита включается при первом запуске «Claudeguard» из меню (или `claudeguard install` в терминале): пароль спросит polkit или sudo.

- Kill switch: юниты `claudeguard-firewall.service` и `.timer` в `/etc/systemd/system`.
- Прокси: пользовательский юнит `claudeguard.service` (`systemctl --user`), лог в `journalctl --user -u claudeguard`.
- Claude Code: `HTTPS_PROXY` и `HTTP_PROXY` в `~/.claude/settings.json`.
- Значок в трее запускается при входе (`~/.config/autostart`). Нужен трей с поддержкой StatusNotifier: в KDE он есть, в GNOME нужно расширение AppIndicator (в Ubuntu включено).
- Официального десктоп-приложения Claude для Linux нет. Если стоит неофициальная сборка (`claude-desktop` в PATH), в меню появится «Claude via Proxy».
- Нужны systemd и `nftables` либо `iptables`; пакеты тянут `nftables` сами.

**SteamOS.** Системный раздел там только для чтения, пакеты pacman не переживают обновление. Поэтому ставь из архива в режиме рабочего стола:

```bash
tar xzf claudeguard_*_linux_amd64.tar.gz
./claudeguard install
```

Программа копируется в `/opt/claudeguard`, юниты — в `/etc/systemd/system`; оба места на SteamOS переживают обновления системы. Для sudo на Steam Deck сначала нужен пароль пользователя (`passwd`).

**Перед удалением пакета** выполни `claudeguard uninstall` (или «Удалить Claudeguard…» в панели): удаление пакета снимает kill switch и системные юниты, но не трогает настройки в домашнем каталоге.

### Установка из терминала

Работает на всех системах и принимает параметры:

```bash
claudeguard install --ssh vd-poland --allow-tunnels
```

`--ssh HOST` добавляет сервер и делает его активным. Для SSH-сервера claudeguard сам держит `ssh -N -D 127.0.0.1:<свободный порт> HOST`: поднимает при старте и перезапускает после сна, смены сети или обрыва. Нужен вход по ключу без интерактивного пароля (`BatchMode=yes`). Ключ хоста должен быть подтверждён: либо он уже есть в `known_hosts`, либо его подтверждают в панели (см. ниже). Туннель всегда идёт с `StrictHostKeyChecking=yes`, что бы ни стояло в `~/.ssh/config`. Если прокси уже есть, вместо `--ssh` укажи `--upstream socks5://host:port` или `--upstream http://host:port`. Можно не указывать ничего и добавить серверы потом в панели.

## Панель настроек

```bash
claudeguard ui
```

Открывает панель в отдельном окне (то же делают «Claudeguard.app», ярлык «Claudeguard» и пункт «Открыть Claudeguard…» в значке). Если прокси не запущен, `ui` запустит его сам. Чем показано окно:

- **macOS:** собственное окно приложения (WKWebView), со значком в Dock, пока оно открыто.
- **Windows:** окно на WebView2. Он входит в Windows 11 и ставится вместе с Edge на Windows 10; если его нет, панель откроется в браузере.
- **Linux:** окно без вкладок и адресной строки в Chromium, Chrome, Brave, Edge или Vivaldi, с отдельным профилем. Если ни одного из них нет, панель откроется в браузере по умолчанию.

`claudeguard ui --browser` открывает панель в браузере: это страница `http://127.0.0.1:41080/ui`. В панели:

- **Состояние:** через какой сервер сейчас идёт Claude, IP выхода и отклик до Anthropic. Если сервер не отвечает, видно ошибку ssh и кнопку переключиться на другой.
- **Серверы:** список, нажатие на строку делает сервер активным. Переключение мгновенное, Claude перезапускать не нужно: мост берёт новый сервер для каждого нового соединения. «Проверить» поднимает временный туннель и меряет отклик и IP выхода, не трогая активный сервер. «Добавить сервер…» настраивает новый SSH-сервер или берёт готовый хост из `~/.ssh/config`.
- **Защита:** состояние kill switch (панель сама пробует достучаться до Anthropic напрямую), переключатель «Пускать через VPN» (`--allow-tunnels`) и дополнительные сети. «Применить» просит пароль администратора и переустанавливает правила.
- «Перезапустить Claude» закрывает приложение и открывает его через прокси, то же самое, что «Claude via Proxy».

### Новый SSH-сервер

«Добавить сервер…» → «Настроить новый сервер»: адрес, пользователь, порт и пароль. Дальше Claudeguard сам:

1. Показывает отпечаток ключа хоста, если сервер ему ещё не знаком. Сверь его с тем, что показывает сам сервер (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` в консоли хостера). Если ключ отличается от записанного в `known_hosts`, настройка останавливается: так выглядит и переустановка сервера, и перехват соединения.
2. Входит по паролю и дописывает свой ключ в `~/.ssh/authorized_keys` на сервере. Пароль нужен один раз и нигде не сохраняется.
3. Проверяет, что сервер пускает туннели (`AllowTcpForwarding`), входит уже по ключу и меряет отклик до Anthropic.

Ключ Claudeguard (`id_ed25519`, права 0600) и подтверждённые ключи хостов (`known_hosts`) лежат рядом с `config.json`. Твои `~/.ssh/config` и `~/.ssh/known_hosts` приложение не меняет. Сервер за ProxyJump или ProxyCommand так не настроить: подтверди его ключ командой `ssh` в терминале и добавь как готовый хост.

Если сервер из списка отвечает «Ключ хоста не подтверждён», под его строкой появляется отпечаток и кнопка «Доверять ключу».

### Значок в строке меню

```bash
claudeguard tray
```

Показывает, через какой сервер идёт Claude и стоит ли kill switch, переключает серверы, открывает панель и перезапускает Claude через прокси. Сплошной щит со стрелкой — Claude в сети, контур с чертой — офлайн. Это отдельный процесс: «Убрать значок» прокси и kill switch не трогает.

### Тема

Панель следует системной теме. Переключатель «Авто / Светлая / Тёмная» внизу страницы. Цвета взяты из палитры Claude desktop.

Типы серверов:

- SSH-сервер: настроенный в панели, алиас из `~/.ssh/config` или `user@host`. Туннель claudeguard держит сам.
- SOCKS5 или HTTP-прокси, в том числе с паролем: `http://user:pass@proxy.example:3128`, `socks5://user:pass@host:1080`.
- Прокси от VPN-клиента (Amnezia, v2ray, sing-box и т. п.): его локальный SOCKS или HTTP порт.

Список хранится в `~/Library/Application Support/claudeguard/config.json` (Windows: `%APPDATA%\claudeguard\config.json`), права 0600. Путь можно переопределить переменной `CLAUDEGUARD_CONFIG`.

Панель живёт на том же порту, что и прокси, а до него может достучаться любая программа на этом компьютере. Поэтому:

- каждый запрос к API несёт ключ из конфига. В ссылку он попадает после `#`, браузер его на сервер не шлёт и из адресной строки он стирается. `claudeguard ui` открывает ссылку через личный файл, так что в списке процессов ключа нет;
- перед тем как отдать ключ, `ui` и значок проверяют, что на порту именно твой claudeguard (ответ на случайное число, подписанный ключом), а не чужая программа;
- запросы с чужим `Host` или `Origin` отклоняются, страницу нельзя встроить во фрейм;
- порт SSH-туннеля мост использует, только пока его слушает запущенный им же ssh. Каждый перезапуск туннеля берёт новый порт.

## Проверка

```bash
claudeguard status
```

```
server:          vd-poland (ssh vd-poland)
local proxy:     http://127.0.0.1:41080 running (claudeguard 0.3.0 -> vd-poland)
firewall rules:  installed
via proxy:       ok (api.anthropic.com reachable through the proxy)
direct IPv4:     blocked/unreachable (connection refused)
direct IPv6:     blocked/unreachable (no route to host)
```

Ручной тест kill switch:

```bash
curl --noproxy '*' -m 5 https://api.anthropic.com    # должен упасть сразу
curl -x http://127.0.0.1:41080 https://api.anthropic.com -o /dev/null -w '%{http_code}\n'   # 404/401: дошли
# в панели выбери сервер, который не отвечает (или удали активный)
curl -x http://127.0.0.1:41080 https://api.anthropic.com   # ошибка 502, напрямую тоже нет
```

В режиме `--allow-tunnels` при включённом VPN первая команда пройдёт: трафик идёт через VPN. Выключи VPN, и она начнёт падать.

## Команды

```
app                      то, что делает двойной щелчок: установить, если нужно, и открыть панель
install / uninstall      всё сразу / всё убрать
ui [--browser]           панель настроек в окне (или в браузере)
tray                     значок в строке меню / области уведомлений
status                   проверка
launch [--app PATH]      перезапустить десктоп через прокси
serve [--detach]         прокси и панель (обычно их запускает LaunchAgent / автозагрузка)
enable / disable         только правила файрвола (admin)
```

Опции `install`: `--ssh HOST` или `--upstream URL` (добавить сервер и сделать активным), `--listen`, `--allow-tunnels`, `--extra-block CIDR,CIDR`, `--no-settings`, `--no-launcher`, `--no-tray`.

## Ограничения (честно)

- **Блокируются только сети Anthropic.** Часть служебного трафика Claude идёт на чужие CDN: обновления Claude Code с `storage.googleapis.com`, `downloads.claude.ai` на Google Cloud, сторонняя телеметрия. По IP их не заблокировать без вреда для остальной системы. При запуске через лаунчер (десктоп) и с `settings.json` (Claude Code) этот трафик тоже идёт через прокси, но kill switch его не страхует. Дополнительные сети можно добавить через `--extra-block`.
- **DNS-запрос** к `claude.ai` при запуске в обход лаунчера уходит в системный резолвер. Сам трафик при этом блокируется.
- **Десктоп, запущенный из Dock или Spotlight**, а не через «Claude via Proxy», работает без флага прокси, то есть офлайн (kill switch). Лечится перезапуском через лаунчер.
- **claude.ai в браузере** тоже попадает под блок. Значит, в браузере его тоже нужно открывать через прокси или VPN.
- **`settings.json` env** действует и на дочерние процессы Claude Code (Bash, MCP-серверы): `curl`, `gh` и прочие тоже пойдут через прокси.
- **Основной процесс Electron** (Node-запросы десктопа, не Chromium) флаг `--proxy-server` может не учитывать. В режиме `--allow-tunnels` такие запросы идут через VPN, в режиме «только прокси» блокируются, и часть функций десктопа может не работать без VPN.
- Что вкладка Code в десктопе читает `env` из `~/.claude/settings.json`, не проверено. Kill switch её в любом случае страхует.
- **Claude Cowork** исполняет задачи в отдельной виртуальной машине. Говорят, что через прокси он не работает; здесь это не проверялось. Ожидаемо: в режиме «только прокси» Cowork останется без сети, с «Пускать через VPN» и включённым VPN должен работать. Покрывает ли kill switch трафик из его ВМ, тоже не проверено.
- **Windows** собран и проверен только кросс-компиляцией и unit-тестами. На живой Windows-машине не запускался, в том числе установщик, удаление, значок в трее и мастер настройки сервера.
- **Windows с `--allow-tunnels`:** список физических адаптеров фиксируется при установке. Новый адаптер и `vEthernet` от Hyper-V/WSL правилом не покрыты.
- **Значок в строке меню** на macOS запускался и работал с API, но глазами в строке меню не проверен.
- **Установщики для macOS и Windows** (Claudeguard.app, ClaudeguardSetup.exe) собраны, но двойным щелчком не запускались: проверены сборка, подпись и структура, а окна установки и запрос пароля — нет.
- **Окно панели** на macOS проверено скрытым самотестом: страница загружается в WKWebView и принимает ключ. Само окно, меню, диалоги подтверждения и значок в Dock на экране не проверялись. На Windows и Linux окно проверено только сборкой.
- **Linux** проверен в виртуальных машинах Ubuntu, Fedora и Arch без рабочего стола: установка из пакетов и из архива, kill switch (nftables и iptables), SSH-туннель, восстановление правил таймером, удаление. Не проверены: запуск из меню приложений, окно пароля polkit, значок в трее, SteamOS на настоящем устройстве.
- **Linux, «Применить» и удаление из панели** вызывают `pkexec` из фоновой службы. Если окно пароля не появится, панель покажет команду для терминала.
- **Проверка защиты** в панели и `claudeguard status` сами пробуют соединиться с Anthropic напрямую. Пока kill switch не установлен, такая проба доходит до Anthropic с твоего настоящего адреса (TCP-соединение без запроса).
- **Удаление** проверено в виртуальной машине Ubuntu: состояние до установки и после удаления совпало (файлы в домашнем каталоге, `settings.json`, `authorized_keys`, правила nftables, юниты). На macOS и Windows удаление проверено только unit-тестами и сборкой: перенос приложения в Корзину, очистка данных окна и удаление из «Приложений и возможностей» вживую не запускались. Остаются пустые `/usr/local/bin` (macOS) и `~/.local/share` (Linux), если их создала установка.
- **Кнопка «Применить»** на macOS проверена только до вызова: диалог пароля и переустановка правил pf на этом Mac не запускались. Переключение серверов, проверки и туннели проверены вживую.
- **Пароль от прокси** хранится в конфиге открытым текстом (файл доступен только твоему пользователю). В панель он не выдаётся.

## Аналоги

- [ProxyBridge](https://github.com/InterceptSuite/ProxyBridge): open source (MIT), Windows и macOS, правила по процессам (proxy/direct/block). Самый близкий аналог. Правило block можно использовать как kill switch, но оно привязано к процессу, а не к адресам.
- [ProxiFyre](https://github.com/wiresock/proxifyre): только Windows, SOCKS5 по процессам через NDISAPI, умеет UDP.
- [Proximac](https://github.com/csujedihy/proximac): только macOS, CLI в духе Proxifier.
- [sing-box](https://sing-box.sagernet.org/): TUN с правилами `process_name`. На Apple-платформах нет `strict_route`, а без него нет жёсткого kill switch.
- Proxifier: платный, правила по приложениям.

## Сборка

```bash
go test ./...
./build.sh                # все установщики и пакеты в dist/
go run ./tools/mkicon     # перерисовать значки в icons/
```

`build.sh` запускается на Mac с Xcode Command Line Tools: значку в строке меню нужен cgo, а `.dmg` собирает `hdiutil`. Windows и Linux собираются без cgo. Пакеты `.deb`, `.rpm` и Arch делает [nfpm](https://nfpm.goreleaser.com/), значок в `.exe` вшивает `rsrc`; оба скачиваются через `go run`.

Панель (`ui/`) встраивается в бинарник через `go:embed`, отдельно ничего ставить не нужно. Готовые бинарники лежат в Releases.

Макет панели в Claude Design: https://claude.ai/artifact/3bjRyRajb78edZDhGEPKgm
